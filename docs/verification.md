# Проверки Attendance

## API и база данных

Тесты используют отдельную PostgreSQL. Защита проверяет, что имя базы заканчивается на `_test`, перед очисткой тестовых таблиц.

```sh
docker run --rm -d --name attendance-tests-db -e POSTGRES_DB=attendance_test -e POSTGRES_PASSWORD=test-only-password -p 127.0.0.1:55432:5432 postgres:18-alpine
python -m pip install -r backend/requirements-test.txt
TEST_DATABASE_URL=postgresql://postgres:test-only-password@127.0.0.1:55432/attendance_test python -m pytest backend -q
```

В PowerShell переменная задаётся командой `$env:TEST_DATABASE_URL='postgresql://postgres:test-only-password@127.0.0.1:55432/attendance_test'`. Тесты покрывают границы действия QR, смену и закрытие сессии, геозону и точность, статус опоздания, чужое расписание, доступ к отметкам, JWT, ротацию refresh-токена и параллельную отметку группы.

## Браузер и мобильный клиент

- Playwright использует отдельный стенд с учебными данными и активным занятием без сессии. Установите Chromium через `npx playwright install chromium`, передайте `DEMO_PASSWORD` через окружение и запустите `npm run test:e2e --workspace @attendance/web`. Адрес стенда задаётся через `ATTENDANCE_QA_URL`.
- Браузерный сценарий декодирует QR-код из интерфейса преподавателя, отправляет его в API как студент, отправляет геоотметку второго студента и проверяет обе строки в списке. Сценарий также меняет время, закрывает регистрацию, проверяет восстановление входа и выход.
- Для проверки на смартфоне проверьте вход, QR с другого экрана, разрешение и отказ камеры, геолокацию в зоне и за её пределами, задержку получения координат, отсутствие сети и повтор запроса. После перезапуска приложения проверьте восстановление входа и историю. Повторите проверку на Android и iOS.

Аудит npm сообщает о транзитивной зависимости picomatch в цепочках инструментов сборки. На момент проверки подходящая исправленная версия отсутствовала в npm.
